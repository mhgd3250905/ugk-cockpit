# 测试入口

日常编辑后运行 `npm run test:quick`，再对本次修改运行相关定向测试，例如 `npm test -- test/setup-codex.test.mjs`。快组目标约 30 秒，实际时间取决于机器；它只覆盖明确挑选的低成本反馈项，输出成功不代表完整门禁通过。

`scripts/run-quick-tests.mjs` 维护快组清单，两个独立文件进程并行，文件内部保持默认串行。新增快组文件前核对临时目录、端口及用户环境隔离并计时；真实 Git 工作流、迁移、崩溃恢复与杀进程测试仍在完整套件中。未知新测试文件不会因为未加入快组而从完整套件遗漏。

`npm test` 保持 Node 的全量自动发现及串行文件执行，包含 Phase 0；也保留 `npm test -- test/某文件.test.mjs` 的定向用法。所有入口先检查测试目录和声明，防止空测试绿灯。测试编排修改需要核对发现范围、清单无重复/缺失以及错误退出码传播。

CI 先在快速 job 执行快组和实际 `npm run build:web`，成功后由两个独立 Windows runner 执行 `npm test -- --test-shard=1/2` 与 `npm test -- --test-shard=2/2`，各自仍为文件串行。两片合计完整覆盖，每项在完整门禁中执行一次（快组会先额外提供反馈）；两片均成功才算完整门禁通过，任一失败不取消另一片。同一候选完整套件已包含 Phase 0，不再运行第二遍；`npm run test:phase0` 保留用于独立诊断。完整门禁失败不得由快组通过替代。

发布候选还须按项目约定完成独立 readiness 审核；迁移与恢复协议改动保留历史数据、真实进程重建和终止验证。已通过且代码树、平台及相关配置未变化的证据可以复用，说明证据对应的候选。不要同时在同一机器启动多套完整测试；启动器测试目前使用固定测试端口。
