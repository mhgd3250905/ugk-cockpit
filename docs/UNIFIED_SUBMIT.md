# 统一分支交付送审

状态：初版 `0.1.0-alpha.29` 已实现并完成下述本地验收（2026-09-03），原始基线 `bae906e` / `0.1.0-alpha.28`；内容范围修正随 `0.1.0-alpha.30` 交付，增量与用户实测记录见文末。项目当前版本以根目录 `VERSION` 为准。

## 用户需求与不变量

用户完成分支任务后显式调用 `cockpit-submit`：确认项目与本次交付范围、保存必要提交、普通推送、建立主项目审核待办，并从平台复制审核指令给 main Agent。开发前是否 init、是否由平台创建分支、是否换过聊天都不是交付必须满足的条件。平台不追管外部开发历史，不伪造旧会话、Agent 归属或验证结果。

送审必须先通过 MCP 核对已登记项目、代码位置授权和当前实际分支，比较最新远端目标版本。不能以过期本地 main 或聊天中的分支名作为事实。普通用户不提供路径、token 或内部 ID；MCP bridge 注入自身 cwd，首次使用未授权目录时，通过系统选择器显式授权并核对真实路径及 Git metadata 边界。

不存在项目或多个候选时，停止并请用户在平台登记/确认；不能默默注册新项目。受管空间与独立 clone 都可作为来源，但来源本地身份与远端目标仓库身份必须分别核验，不能伪装成同一个 worktree。

## 流程与前置检查

1. 定位当前目录对应的授权来源以及已登记主项目；无 session 时不要求 init。若存在其他 active write lease，不抢占、不结束它：只读接纳已上传且无未提交改动的成果可以继续，修改该目录必须具备原会话权限。
2. 完整列出 tracked/untracked 改动；Agent 按用户任务明确选择本次包含的文件。保留不相关、忽略文件和未纳入交付的改动；对疑似凭据文件停止，不自动 `add --all`。
3. 在临时隔离 Git 数据区检查所选改动的完整候选树、最新远端 main、源分支远端进度和合并关系。检查不修改源/主项目的 HEAD、分支、index 或工作文件，也不执行仓库脚本、hooks、filters。
4. 结果区分：可送审、存在冲突、已合入/无新成果、重复送审、远端分叉、检查未完成。分支较旧不等于冲突；目标更新导致非快进也不能误标为文件冲突。冲突需显式确认才能保存为“需要解决冲突”的待办，不能标记可合并。
5. MCP 返回短时 preflightId，绑定来源、项目、源 HEAD/候选树/所选文件、目标远端 HEAD 与状态。执行 submit 时重新核对，过期或内容变化需重新检查。
6. 无新改动不制造提交；已有提交/上传不重复制造。普通 push，禁止 force、reset、自动 rebase、切换分支、清理。提交成功而推送失败必须报告“本地已保存，远端尚未送达”，用同一幂等键与 payload 恢复。
7. 实际上传的 SHA 经核验后登记审核任务；复制指令绑定任务 ID/版本及源/目标 SHA。审核不是自动合并授权，合并前重新检查。已有 GitHub PR 可作为交付引用，不将 Agent 声称的 PR 状态当作服务端证明。

Windows HTTPS 只复用本机 Git for Windows 安装的 Credential Manager，关闭交互登录与仓库自定义 credential helper；平台不读取、展示或传递用户 token。SSH 使用系统已有配置。不安装认证工具、不替用户登录；缺少现有认证时明确停止。测试使用本地 bare remote，不冒充已验证真实托管平台凭据。

## 待办与跨机边界

同一来源分支到同一目标是一条交付线；同一 SHA 重复送审复用，后续 SHA 形成新版本并令旧审核失效，保留历史回执。已合入、已关闭等状态不冒充平台审核事实。

本机项目正在开发、有未提交改动不应阻止建立待办。当前 `ff-only` 合并能力保守保留；非快进、目标变化或本机有改动必须显示明确后续动作，不能为新入口绕过既有合并门禁。独立 clone 的审核对象需要进入服务管理的隔离副本，以固定 SHA 供审核读取；审核副本不是执行不可信脚本的安全沙箱。

远程 Agent 无法连接本机 MCP 时，输出待接入交付信息（远端地址/分支/完整 SHA/可选 PR/摘要），不可声称已送达平台，不共享本机 token。平台接收后必须自行核验，不信任消息中自报的通过结论。跨机可达性与远端托管平台合并 API 不在本次本机送审能力中伪装完成。

## 实施计划与验收

1. **需求与基线**：确定授权入口、MCP 契约、来源与交付数据关系；Agy 只读核对安全缺口。
2. **Git 检查与保存**：实现完整候选树、隔离冲突检查、远端源/目标核验、精确范围 commit、非强推和内容变化防护；Agy 负责有界 Git 模块及临时夹具测试。
3. **接入与回执**：新增不依赖旧 session 的 preflight/submit 路由、持久化幂等恢复、重复/新版管理、平台待办与复制指令；主会话负责整合。
4. **Skill 与用户路径**：统一 cockpit-submit，保持显式调用；缺授权/远端不可达/冲突必须如实说明。同步已安装的共享与 Codex Skill，不改其他技能。
5. **独立验收与版本**：Agy 新 conversation 审查最终实现；主会话运行针对性测试、`npm test`、`npm run test:phase0`、`npm run build:web`、`git diff --check`，记录证据后形成本地可回退 commit。未经另行授权不 push、打 tag 或修改业务仓库。

测试矩阵覆盖：未 init 的 clone/额外 worktree、换聊天、受管空间换分支、项目不存在/歧义/身份替换、源 main/detached、无新成果/重复/新版、未提交内容变化、范围外改动保留、敏感路径、远端领先/分叉/不可达、陈旧但无冲突/真实冲突、push 失败和崩溃恢复、目标并发变化、审核指令绑定、路径和 lease 边界。所有自动化 Git 写操作只发生在测试创建的临时仓库。
