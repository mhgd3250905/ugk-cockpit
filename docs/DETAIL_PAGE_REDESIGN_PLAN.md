## 推荐信息结构

| 一级入口 | 用户的问题 | 内容与动作 |
| --- | --- | --- |
| 概览（默认） | 现在怎么样，接下来做什么？ | 当前工作目标、最近记录与时间、需要我处理的事项、明确的 AI 工作会话与接手入口；最近 3 条进展预览。 |
| 工作记录 | 之前发生过什么？ | 原时间线、日期分组、工作线突出显示、完整原文、加载更早记录、工作线结束/重新打开。 |
| 工作说明 | 有哪些成果或建议需要我处理？ | 现有收件箱、待处理/已处理/归档筛选、说明正文、引用、复制、处理备注和状态操作。导航仅显示待处理数。 |
| 工作副本 | 去哪里并行做一项功能？ | 现有开发空间、创建、复制 AI 接入消息、对应会话、重新开始、删除及未确认操作核对。导航显示可用副本数，并明确是否包含已删除历史。 |
| 设置 | 怎么改项目资料或排查问题？ | 名称/头像、代码位置、诊断、归档/恢复、从工作台移除。资料、诊断、项目管理分组，不平铺所有操作。 |

导航描述可用“当前情况 / 开发历史 / 成果与待办 / 并行开发 / 项目资料”。描述放在各页标题下或垂直导航中，避免顶部堆满说明。

| 现有功能/位置 | 规划位置与展示规则 |
| --- | --- |
| 编辑项目（标题右侧） | 设置 → 项目资料，保留现有编辑流程。 |
| 归档/恢复、从工作台移除（更多操作） | 设置 → 项目管理，分别解释是否保留列表、代码与历史。 |
| 当前目标、平台、版本、文件状态（工作概况弹窗） | 概览显示可读摘要与记录时间；技术字段按需展开。 |
| 会话持有人、转交、取消转交、位置确认、原请求核对（弹窗底部） | 概览的“AI 工作会话”独立可见入口；具体操作按工作线和真实状态出现，不把转交做成直接执行按钮。 |
| 历史已结束会话 | 会话详情中的历史折叠区，默认显示当前相关会话。 |
| 时间线、突出显示、加载更早、记录原文 | 工作记录保留；“突出显示”不改成“筛选”，避免误导为隐藏其他历史。 |
| 手动结束/重开工作线（选择工作线后才显示） | 工作记录 → 当前选中工作线标题区的文字菜单；明确是用户标记，并非结束 AI 会话或删除副本。 |
| 说明复制、手动复制、标记处理、恢复待处理、归档、处理备注 | 工作说明内清楚分成“阅读与复制”和“处理状态”；正文详情可用侧边面板，保持复制反馈稳定。 |
| 发布说明指导、旧代码送审记录 | 工作说明 → 如何提交 / 历史送审，作为辅助入口。 |
| 新建空间、复制接入消息 | 工作副本的主动作与条目操作；创建前解释用途。 |
| 重新开始、删除空间 | 副本条目的文字菜单，含明确影响说明及原确认；不能只用垃圾桶图标。 |
| 未确认空间操作 | 概览“需要处理”出现提示并链接至该副本；原请求材料继续留在原事实源。 |
| 项目路径、ID、近期脱敏会话诊断 | 设置 → 代码位置 / 诊断；不再放在长历史后面。 |

## 概览的阅读顺序

1. 项目名与平台标签，下面是一句准确状态和最近记录时间。
2. 当前工作：工作目标与一项按真实状态选择的推荐入口。普通状态可为“查看会话与接手”，异常状态优先“核对未确认操作”或“确认代码位置”。按钮先打开对应流程，不暗中执行授权或写操作。
3. 需要我处理：待处理说明、待接手、未确认操作、代码位置异常按真实数据列出，正常时简短说明，不放空占位卡片。
4. 最近进展：3 条短摘要，入口“查看全部工作记录”。完整历史保留在记录页。

首屏可读摘要不从最后一条 progress 自动推断“完成”“在线”或“已合并”。如果最新记录是旧的，要显示时间，不能用“刚刚更新”补齐。

## 视觉规则

- 沿用石墨暗色、近白亮色、品牌橙。字号以 14–16px 为主体，项目标题 28–30px；辅助时间 12–13px。
- 固定全局项目导航，详情内部导航位置稳定。使用留白、标题和分隔线建立层级，减少卡片套卡片。
- 正文区域避免无限拉长；概览可用主区与 300–340px 辅助区，工作说明可用列表与正文侧栏。
- 常用动作采用明确动词和 Lucide 图标；图标不能替代重要按钮文字。页签计数不仿通知红点，只有真实待办才强调。
- 每个内容区最多一个明显主按钮；项目设置、刷新、查看原文为次级。删除等动作不与复制接入处于同等视觉权重。
- 详情顶部的全局“添加项目”收为次级或侧栏入口，避免与当前工作主动作竞争；项目资料与管理不重复放在标题旁和设置中。生成草案中的遗留标题操作仅作为参考偏差，最终按功能迁移清单收束。
- 卡片/列表是首页布局偏好；详情建议选定一套结构，并同时支持深浅主题，避免再增加多种操作地图。

三个视觉草案比较布局而非新增业务能力：概览主区+会话辅助区、浅色横向分组列表、带用途说明的垂直功能导航。生成图为布局示意，不能作为实际业务状态或已实现页面。

## 实施顺序与验收目标

第一步重组导航与功能入口，复用现有组件和请求逻辑。第二步完成概览与状态摘要；跨模块提示若需要额外汇总接口，明确接口范围并单独验证，不用已加载历史页数代替总数。第三步统一工作说明、工作副本和设置的视觉与确认流程。

| 验收任务 | 目标 |
| --- | --- |
| 找到聊天接手 | 首屏明确入口，一次点击进入对应会话管理；随后保留授权确认。 |
| 找到待处理说明 | 详情导航即见真实数量，一次点击进入收件箱。 |
| 找到并行开发 | 工作副本入口和用途解释可见，不要求理解 worktree。 |
| 查看历史 | 工作记录可达，既有轨道、来源、时间顺序与加载行为不变。 |
| 处理异常 | 说明发生了什么、代码是否受影响和推荐下一步；核对继续使用原请求。 |
| 管理项目或副本 | 归档、移除、结束工作线、删除副本的影响明确区分，原确认与守卫保留。 |
| 桌面表现 | 1280、1440、1920px 深浅主题检查，键盘导航与弹窗焦点复核；不含手机验收。 |

会话转交授权立即冻结原聊天推进权、10 分钟有效且超时不自动恢复；接手指令仍只在当前页面状态中显示，不写 URL、持久存储或普通进展。未知作者/代码状态不得猜测。工作说明“已处理”仍不代表已合并。删除忽略文件、复用副本的版本变化、已有未确认请求的恢复依据全部沿用现有契约。
