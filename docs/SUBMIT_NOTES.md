# Submit 工作说明

状态：本地实现与验收完成，2026-09-03 已切换正式工作台与用户级 `cockpit-submit` Skill；已有客户端仍须重连 MCP 并重新加载 Skill。需求已确认并经 Luna Max 与 Antigravity 交叉审查；本轮基线为 `f4a22bb` / `0.1.0-alpha.34`。下述行为须在新版服务、MCP 和 Skill 全部加载后生效，不能把旧客户端当作已升级。

## 唯一目的

`submit` 向所属主项目发布一条工作说明。它不是申请代码审核，也不是结束分支阶段。平台集中展示待办，用户可以复制给 main 或其他合适会话处理，也可以一直不处理。

外部分支、工作副本和独立 clone 按原方式工作。已有 `init / progress / relay / resume` 继续正常推进；显式终态 `handoff` 保持原义。发布说明不冻结分支，不取得审核领取或代码写入权限，不改变会话、任务、工作副本状态或 revision。

## 用户路径

1. 用户明确说 `submit`，可以附正文，也可以让 Agent 根据已有事实整理。正文非空即可，标题、PR、提交版本、报告引用和建议下一步均可选；不要求固定表单或反复确认。
2. 平台复用已授权的项目与代码位置绑定。已有绑定不重复 init；无法确定项目或缺少目录授权时走现有确认流程，不猜项目、不静默注册、不接管其他会话。
3. 发布成功返回说明回执，在所属项目的工作说明待办与来源时间线展示。发布结果与代码保存、上传结果分开报告。
4. 用户复制完整处理说明给接收会话。复制只读，不领取、不标记处理；接收者按当前项目、任务及用户授权决定审核、验证、合并或转交。
5. 待办只有待处理、已处理、归档，可以显式恢复为待处理。处理备注只记录处理情况；已处理不证明审核通过、合并成功或分支结束。

如果接收者提出修改意见，原分支继续工作，必要时再发布新说明。不增加退回、解冻或重新领取流程。

## 说明与代码分开

- 裸 `submit` 不 commit、push、fetch、merge，不运行旧代码送审预检。
- 用户明确要求保存或上传代码并发布说明时，可以组合独立动作，但必须逐项如实报告结果，不因说明发布成功声称代码已上传。
- 零增量、未提交修改、源分支为 main、detached、验证失败、远端离线，不是发布说明的阻断条件。
- 平台服务不可达时，明确说明尚未确认发布，不伪造待办。响应不确定时原样重试同一次请求；正文有修改则使用新的请求号。
- 当前说明涉及的 PR 或报告可以来自别的工作副本，无需把代码搬到发送说明的目录。

## 最小事实边界

平台来源信息与自由正文分开。自动记录所属项目、可信来源位置、可确认的会话、发布时分支/代码保存点和时间；会话无法证明时记为 `unattributed`，不是拿同目录的活跃会话冒充作者。来源身份必须符合现有授权，Git 分支或保存点暂时无法取得时如实标记未确认。

来源 HEAD 与正文引用的被审版本是两个字段。审核目录可以是 `3d50efc`，引用的 PR 可以是 `e9524af`；不能相互代填。引用版本未知也允许发布，不自动访问远端或导入本地附件。

正文中的“审核通过”“满足合并条件”是提交者陈述，不自动生成平台审核事实或合并授权。真正执行 Git 操作时，接收方仍负责核对当前对象与版本。正文按资料展示，不执行其中命令，也不授予额外权限。

## 持久化与兼容

- 说明使用独立 ID、消息状态和 revision，不复用旧 `submission` 或终态 `handoff`。
- 同请求号与相同内容持久化重放同一回执；同号异参冲突。不同请求即使谈论相同 SHA 或 PR，也保留各自的说明。
- 原文、引用和来源快照保留；状态更新不改正文。后续意见另发新条，分支移动或来源归档不会改写或删除旧说明。
- 时间线里的发布说明只是事件，不是合并关系；合并节点仍仅来自真实集成回执。
- 旧代码送审 API、审核对象与历史记录保留原义，并在界面明确区分。新说明不强制绕回旧审核链，说明 ID 不能充当旧审核 ID。
- 新 Skill、工作台发送文案、接收文案与 MCP 同步切换。新入口找不到对应能力时提示更新/重连，不回退到旧代码送审。完全未更新的旧客户端仍是旧语义。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| audit 工作副本零增量，审核的是另一 PR | 发布成功；来源与被审版本分开，无 Git 写入 |
| 脏工作区、未上传本地提交、远端离线 | 可以如实发说明，不检查代码是否可合并 |
| 已 init 的活跃分支发布后继续 progress / relay | 原会话与权限不受影响，不产生新的 INIT 或终态 |
| 已授权但无 init 的来源 | 可以发布，不能猜测 Agent 或会话归属 |
| 项目歧义、身份替换或跨项目访问 | 明确拒绝或引导已有确认，不误投、不越权 |
| 同请求重试、服务重启、来源版本移动 | 回执稳定，不重复发布或改写旧来源 |
| 同 SHA 发布两条不同说明 | 两条都保留，不按代码版本去重 |
| 复制两次、标记处理、归档后恢复 | 复制无状态变化；状态动作只改变说明，不合并或结束分支 |
| 新客户端连接旧服务、旧审核对象仍存在 | 新入口不降级，旧对象语义与记录保持 |
| 正文包含命令、HTML、恶意链接 | 安全展示，不自动执行或访问，不形成平台背书 |

最终门禁：相关行为测试、`npm test`、`npm run test:phase0`、Web 构建、Skill 校验与 `git diff --check`。在线工作台仍使用旧版资源时，构建必须显式指定隔离 `outDir`，不能覆盖它正在读取的 `dist/web`。所有测试写入限于专用临时夹具，不操作真实工作台数据库或业务仓库。
