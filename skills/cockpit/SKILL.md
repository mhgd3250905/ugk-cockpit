# UGK Cockpit 使用入口

用一句话介绍：Cockpit 帮你在网页上查看多个项目和 AI 的工作进展，也能在聊天中记录进展、换聊天接力。用户不用学习 MCP 参数或记住所有技能名。

本技能负责安装、启动和使用导航，不创建另一套工作会话开始流程。`cockpit-init` 仍是唯一业务开始入口。按用户当下目标完成对应动作；用户只问用途时，简短说明即可，不自动安装、接入项目或改配置。

## 安装与连接

用户要求安装时，目标是全部配套技能可发现、本机服务可用、当前 Agent 已注册并能实际调用 MCP。下载文件和配置写入成功不等于安装验收完成。

先定位用户提供或本次安装得到的 Cockpit 程序目录，读取其 README 的安装说明。从已安装插件加载本技能时，读取相对于本技能目录的 `../../installed-location.json`，使用其中的 `repositoryRoot` 定位程序目录，并确认该目录中的 README 和 package.json 可读。记录缺失或目录已移动时，使用用户已提供的安装位置；没有可靠位置则询问程序位置，不把插件缓存或当前业务项目猜成程序目录。安装命令在程序目录执行，后续业务 MCP 调用在用户的项目聊天中执行。

按用户指定或当前实际宿主选择安装命令：Codex 使用 `npm run setup:codex`，ZCode 使用 `npm run setup:zcode`。已安装插件的 `installed-location.json` 中 `host` 字段（`codex` 或 `zcode`）标明该安装所属宿主；它不是聊天身份，不得用于填写或推测业务调用的宿主身份。若安装所属宿主与当前宿主不同，按用户目标安装到正确宿主，不把另一宿主的安装当成当前已连接。

以该版本 README 和命令输出说明为准。ZCode 安装由其专用入口完成插件注册，不改用 Codex 命令配置 ZCode。运行环境按程序的 `package.json` 准备。已有安装或同名配置发生冲突时，保留现有内容，按安装器说明处理，不自行强制覆盖。不要让用户手工拼 MCP 配置、学习注册协议或寻找本地 token。其他宿主先查其实际支持的安装方式，不宣称这些命令能配置所有 Agent。

MCP 桥接进程由 Agent 宿主根据注册配置启动；单独在终端运行 `npm run mcp` 不能证明它已加入当前 Agent。安装后发现并通过当前宿主实际调用 `ugk_work_context`，默认参数为 `{}`。该只读响应可以证明工具通路；无已接入会话不是安装失败，但也不能宣称已开始工作。是否可以记录工作还取决于返回的当前绑定与宿主身份能力，不伪造宿主身份。

若工具尚不可发现，按宿主要求重连 MCP 或打开新聊天，明确告诉用户这一项尚待完成，并在新连接里实际验证。不要为测试安装而调用 init、relay、handoff 或写进度。用户已经提供 `continueCode` 时，直接按 `cockpit-relay` 恢复规则执行，不先用 context 阻挡恢复。

## 启动与打开工作台

用户要求启动时，在程序目录按宿主执行：Codex 使用 `npm run setup:codex -- --start-only`，ZCode 使用 `npm run setup:zcode -- --start-only`。这些入口检查并复用已运行的服务，仅在服务未运行时启动，并核对已有数据。保留正常服务，不为打开网页而重启；不要改用会重启已有服务的 `scripts/launch-cockpit.ps1`。只在当前版本文档明确支持的系统上使用此安装与启动入口。

保留已有数据目录配置。启动或重启后的验收必须包括已有项目列表及详情；不能只看 HTTP 200。启动脚本的项目核对失败，或网页空列表与已有记录不一致时，读取程序目录下的 `docs/LOCAL_SERVICE_RECOVERY.md` 处理，不清库、不重新添加项目、不重新 init，不在服务运行时覆盖数据目录。

给出服务实际返回的网页地址；默认地址为 `http://127.0.0.1:41737`。用户要求打开时使用宿主可用的浏览器入口。安装服务成功但当前 Agent 尚未加载 MCP 时，分别报告网页可用、聊天连接待验证，不能混成“全部可以用了”。

## 按用户意图选择配套技能

只读取当前动作所需的同包技能，并遵循其成功标志、授权条件和重试协议，不在本入口复制或放宽业务协议。相对链接以本技能目录为基准。

| 用户想做什么 | 下一步 |
| --- | --- |
| 第一次把项目交给 AI | 引导在工作台选择并授权项目，复制“交给 AI”完整指令回到该项目聊天；取得 `initCode` 后使用 [cockpit-init](../cockpit-init/SKILL.md)。不扫描并自动导入其他项目。 |
| 记录当前进展 | 使用 [cockpit-progress](../cockpit-progress/SKILL.md)。已有工作会话中的有效 Git 检查点按该技能规则登记。 |
| 换个聊天继续，或收到接力指令 | 使用 [cockpit-relay](../cockpit-relay/SKILL.md)，保留当前阶段。 |
| 向主项目发布工作说明 | 使用 [cockpit-submit](../cockpit-submit/SKILL.md)，说明发布与代码保存上传分别报告。 |
| 使用 `$cockpit-closeout` 核对并收束本阶段 | 使用 [cockpit-closeout](../cockpit-closeout/SKILL.md)。它可能修正文档并创建本地提交，但不结束工作会话。 |
| 明确结束本阶段 | 使用 [cockpit-handoff](../cockpit-handoff/SKILL.md)，按用户选择的结果处理；选择 completed 时执行其收束前置。 |

“完成了”“先这样”等含糊表述不能自动变成提交、收束或结束授权。用户询问收束如何操作时，解释该动作会核对并保存本地成果；现有 closeout 要求显式调用，提供 `$cockpit-closeout` 供其选择。不要为了教程演示执行这些写操作。

首次使用只给当前需要的下一步，例如“在工作台选择项目，将‘交给 AI’指令复制到这个项目的聊天中”。遇到绑定由另一聊天持有或需要平台授权，按相应技能引导回原聊天或工作台转交，不能用重新 init 绕过。

## 结果说明

报告实际完成的结果和用户下一步即可。安装验收区分程序与技能安装、本机服务及已有项目核对、当前宿主 MCP 实际调用三个结果；缺哪一项就说明哪一项待完成。异常说明发生了什么、代码是否受影响以及推荐下一步，不展示凭据或底层请求体。
