# UGK Cockpit 发布工作说明

这个动作只能由用户显式调用。只有用户明确输入 `$cockpit-submit` 或明确要求发布工作说明时使用；不要因测试通过、出现 commit 或任务看似完成而自动调用。

`submit` 向所属主项目发布一条工作说明待办。它不是申请代码审核，也不是结束分支阶段或请求自动合并。发布成功后，说明进入主项目的工作说明收件箱，等待项目负责人或合适会话决定处理、搁置或归档。

## 说明与代码分开

1. **裸 submit 只发说明**：
   - 默认不执行 `git commit`、`git push`、`git fetch`、`git merge`，也不运行旧代码送审预检。
   - 零增量、未提交修改、源分支为 main、detached HEAD、验证失败、远端离线，都不是发布说明的阻断条件。
   - 未提交或未上传的本地文件如实说明，不得声称已交付。

2. **用户明确要求保存或上传时**：
   - 可以配合独立的 Git 流程，但必须分别报告代码保存/上传结果与工作说明发布结果，不能因说明发布成功声称代码已上传。

3. **正文整理**：
   - 用户明确提供正文时直接使用；未提供正文时，根据当前事实和对话上下文简要整理工作进展、发现与建议下一步。
   - 只有存在重大歧义时才询问用户，不固定每次确认。

## 调用工具

调用 MCP 工具 `ugk_work_submit_note`：

```json
{
  "clientRequestId": "<本次唯一幂等键>",
  "body": "<工作说明正文，1..20000字符>",
  "title": "<可选简要标题，最多200字符>",
  "references": [
    {
      "target": "<引用目标，如分支名、PR链接或路径>",
      "type": "pull_request",
      "commit": "<可选关联commit SHA>",
      "title": "<可选引用标题>",
      "note": "<可选简要说明>"
    }
  ]
}
```

### 参数与授权规则

- 所在工作目录、所属主项目与工作副本绑定由 MCP bridge 自动注入，不得手动填写 `path`、`projectId`、`worktreeId`、`sessionId` 或寻找本地 token。
- 已登记授权来源无需补做 init；项目未知、归属有歧义或目录未授权时，引导用户在工作台完成现有确认，不猜测项目或抢占其他会话。发布不会改变已有 `progress / relay / resume` 流程，不冻结或结束分支。
- 来源 HEAD 与正文引用的版本分开，引用版本未知时直接省略，不得用来源 HEAD 冒充被审版本。
- 缺少能力处理：若 MCP 未提供 `ugk_work_submit_note` 工具，提示用户更新或重连 UGK Cockpit MCP 服务，严禁静默回退（fallback）到旧版代码送审 `ugk_work_submit`。

## 重试与幂等

- 传输中断或响应不确定时，使用同一个 `clientRequestId` 和完全相同的请求参数原样重试。
- 若正文有修改，必须生成新的 `clientRequestId`。

## 结果汇报

- **发布成功**：如实报告说明编号 `noteId`、所属项目及当前状态 `pending`（待处理）。提示用户可以在主项目工作台复制说明转交其他会话。严禁声称审核已通过或代码已合并。
- **发布失败**：如实报告错误原因与建议下一步。服务不可达或响应不确定时，只能说“尚未确认发布成功”，不能断言平台没有收到；严禁伪造说明回执。
